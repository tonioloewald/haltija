## Fix before the tag (verified majors)

1. **The REST drag can't drive pointer-event controls, and reports success anyway.** `src/drag.ts:123-165` (dryness, verified)
   `/drag`, `hj drag` and the `{"action":"drag"}` step send mouseenter, mouseover and mousemove through `events/dispatch`. In `component.ts`, `dispatchSyntheticEvent` (around line 11788) builds a real MouseEvent only for click, mousedown and mouseup. Everything else becomes a `CustomEvent` with no `clientX` or `clientY`. The moves and the mouseup that follow are bare `MouseEvent`s with no `buttons` and no `PointerEvent`. Meanwhile `POINTER_KIT` in `src/test-in-browser.ts:167` was fixed for exactly this in the beta.1 review. As a result, a pointer-driven slider, resize handle or orbit camera does not move and the step still passes. The realistic click (`component.ts` around 10150-10171) has the same gap.
   **Fix:** pick one in-page pointer primitive: a PointerEvent plus its MouseEvent twin, with `buttons: 1` while pressed and real coordinates. Use it from `drag.ts`, and from the realistic click if that's practical. At minimum, make the synthetic mouseenter, mouseover and mousemove real MouseEvents. Update the SKILL.md wording on what `drag` can drive.
   **Clearing check:** a Playwright test with a fixture slider that listens only to `pointerdown`/`pointermove` and requires `buttons === 1`. `hj drag` / `POST /drag` / a `drag` step must move it. The test must fail with the fix reverted.

2. **The attested `test:integration` lane ran 0 tests and is recorded as passed.** `release-attestation.json` (coverage, verified)
   `tests/haltija.test.ts` wraps everything in `describe.skipIf(!serverAvailable)`, so it runs only when `HALTIJA_PORT` or `HALTIJA_URL` is set. The attest run set neither. The beta.5 attestation shows `0 pass / 11 skip`, exit 0, 32 ms, and beta.4 was the same (28 ms). `test:all` includes the same empty run. So the `haltija/test` helper and the `/test/run` JSON runner have not been exercised at release, and CI doesn't run them by design.
   **Fix:** make the lane start what it needs. Have `test:integration` spawn `haltija --private --headless`, export the reported port as `HALTIJA_PORT`, then run `bun test tests/`. Then re-attest the 1.13.0 release commit.
   **Clearing check:** the regenerated `release-attestation.json` shows `test:integration` (and the matching stage of `test:all`) with **11 pass, 0 skip**. Re-review scope, if anyone wants one: the test-coverage lens over the lane script and the new attestation only.
   (The matching guard in `attest.ts`, which fails a lane that skips everything, is a shared-practices item; see below.)

## Remediation (2026-10-18, commit 7df797b)
