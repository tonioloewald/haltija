The review names base `v1.12.6`, but **`v1.12.7` and `v1.12.8` are both tagged and published on npm**. `git diff v1.12.8...HEAD` is CHANGELOG + version files only (`_Nothing yet._`). Everything substantive under review — #40 machine control, the stdio channel, the file previews, #43 Electron discovery, the test-lane fix — **has already reached users**.

That does not soften the verdict, it sharpens it: the blocker is live in the field, not hypothetical. **BLOCK here means "do not cut 1.12.9 until it contains these fixes", and the CDN item should be expedited as a patch rather than queued.** It does not mean holding an empty tag.

## Blockers — must be fixed before tagging 1.12.9

### B1. Unpinned third-party CDN script is injected into the one frame that has a relay to shell execution — in the release that removed shell execution from the network
`apps/desktop/terminal.html:2038` · lens: blast-radius · **VERIFIED / CONFIRMED**

`loadBabylon()` appends `<script src="https://cdn.babylonjs.com/babylon.js">` (rolling latest — no version pin, no `integrity`, no `crossorigin`) plus the loaders bundle. Verified chain, every link checked in code:

- **New in this window.** Added by `b176250`, contained in tags v1.12.7 and v1.12.8.
- **Only remote script in the desktop app.** Every other dependency, CodeMirror included, is served from `${BASE_URL}/assets/` on the local haltija server.
- **No CSP.** terminal.html has no `http-equiv`; `main.js:663-680` *deletes* `Content-Security-Policy` headers globally; the iframe (`renderer/tabs.js:243`) carries no `sandbox` attribute.
- **It reaches a shell.** `hjFetch` (terminal.html:879-901) posts `hj-machine-request` → `renderer/machine-relay.js:17` (no origin/source check) → `preload.js` `machineRequest` → `main.js:1339` → server stdio → `src/server.ts` `/terminal/command` → `spawn('sh',['-c',…])` (`src/terminal.ts:419`), plus the whole `/files/*` surface. The stdio path deliberately bypasses the #40 refusal (`!viaMachineChannel`, server.ts:1090).
- **It ships.** `apps/desktop/*.html` is in package.json `files`; trigger is a user opening a `.glb/.obj/.stl` in the file browser.

Net: a CDN compromise, a bad publish, or a corporate TLS-intercepting proxy yields arbitrary shell execution and arbitrary file read/write on the developer's machine. The prior surface was browser-reachable; this one is supply-chain-reachable. Narrower preconditions, same capability — and it lands **inside the security release** whose stated premise (`src/machine-control.ts`, #40) is that "a development tool has no business offering remote code execution."

**Fix:** vendor Babylon + loaders into `apps/desktop/resources/` and load from disk (exactly how CodeMirror is already handled) — preferred, since it also removes a network dependency from a local tool. Minimum acceptable: pin an exact version URL (`https://cdn.babylonjs.com/v<x.y.z>/babylon.js`) with `integrity="sha384-…"` and `crossorigin="anonymous"`. Land together with B3's origin check so a compromised preview script cannot address the relay at all.

### B2. `__NEED_WINDOW__` window recreation is dead code on the public server
`apps/desktop/main.js:1402` · lens: correctness · **VERIFIED / CONFIRMED** (severity was flagged uncertain; confirmed as at-least-major)

The new public-role stdout branch does `machineBuffer += chunk; parts = machineBuffer.split('\n'); machineBuffer = parts.pop()`, then tests `machineBuffer.includes('__NEED_WINDOW__')` — the **residual partial line**. The server emits the marker via `console.log('__NEED_WINDOW__')` (`src/server.ts:1026`, `:4054`), a complete newline-terminated line, so it lands in `parts` and the buffer is `''`. Simulation confirms the check is always false. The branch `return`s, so the still-correct `text.includes(...)` at `:1410` is **unreachable** for the public role — the two paths do not merely disagree, the working one can never run.

Blast radius is **wider than first reported**: `bin/cli-subcommand.mjs:847` short-circuits auto-launch for desktop-app servers (`if (status?.desktopApp) return true`) with a comment explicitly deferring to `__NEED_WINDOW__`. So **every** `hj` command against a windowless-but-alive desktop app (reachable on macOS — `window-all-closed` at main.js:1822 only quits off-darwin) blocks 8s and fails "No browser connected". Only recovery is a manual dock click / `open -a` via `app.on('activate')`.

Regression introduced by `efed30f` (#40); `git log -L 1380,1415:apps/desktop/main.js` shows the pre-change code tested the whole chunk and worked.

**Fix:** test the token on the complete lines inside the loop (or on the raw `data.toString()`), never on the residual buffer. Land with F2 — this is exactly the mistake the shared `splitLines()` would have prevented.

### B3. `/ws/terminal` accepts unauthenticated cross-origin upgrades with no Origin check, so the release's "every transport" claim is false
`src/server.ts:4258` · lens: blast-radius · **VERIFIED / CONFIRMED** (reproduced live against a real server)

WebSocket upgrades are exempt from CORS, and the upgrade path checks only `REQUIRED_TOKEN` (unset by default) — never `Origin`. Live repro on a real server confirmed:

- `GET /files/read` with a foreign Origin → **410**. The #40 refusal genuinely works over HTTP.
- `new WebSocket('ws://localhost:PORT/ws/terminal', {headers:{Origin:'https://evil.example'}})` → **OPEN**, and the first frame is `{"type":"identity","shellId":"shell-1","cwd":"/Users/…"}` — the server's cwd handed to an unauthenticated cross-origin peer unprompted.
- A `/files/read` issued over the **stdio machine channel** produced `{"type":"file-touched","path":"/Users/…/package.json",…}` on that same cross-origin socket. **The pipe removed the request path, not the disclosure path** — stdio-channel effects still egress over the network listener.
- A crafted `{channel:'system',action:'connected',payload:{browserId:'attacker',windowId:'hj-victim-1'}}` on the terminal socket arrived verbatim on a `/ws/browser` socket registered as that windowId — the exact frame `component.ts:9224` kills on (`kill()` sets `killed=true`, permanently stopping reconnect).

**Two honest corrections to the original framing, neither of which rescues the claim:** the socket offers no command execution or filesystem access (nothing on it reaches `dispatchCommand`), so the residual is machine-scope **disclosure** plus injection into the widget broadcast bus, not RCE; and the widget-kill vector is strictly weaker than the cross-origin `POST /eval` the release already openly discloses.

What makes this gating is not the severity of the residual but the **assurance**: the absolute claim "no machine-control surface on any transport at all" appears in three hand-written places — `CHANGELOG.md:110`, `CLAUDE.md:692`, `src/machine-channel.ts:23` — and CLAUDE.md is read by agents as ground truth. A false completeness claim in a security changelog propagates outside the repo.

**Fix (either is acceptable, not neither):** reject `/ws/terminal` upgrades whose `Origin` is not null/file/localhost-app (costs nothing legitimate — the terminal iframe and renderer are local); **or** soften the claim in all three locations to "no machine control over HTTP" and file the WS surface as a tracked follow-up. Do not ship the absolute claim with the path open.

## Follow-ups — grouped by destination

### → this repo's `TODO.md` (correctness / dryness / docs / coverage / dx)

- [ ] **The machine-channel wire protocol is implemented twice, and the tested copy is not the one Electron runs.** *(major, unverified)* `src/machine-channel.ts` owns the prefixes, `splitLines()` and `parseResponseLine()` and is covered by `src/machine-channel.test.ts` — but only the server imports it. `apps/desktop/main.js:1283-1284` re-declares both prefixes as literals and hand-rolls the split loop (`:1388`) and the parse (bare `JSON.parse`, no shape validation) with **no test**. Already-real drift: this is where B2 came from, and main.js resolves a pending request on any id match even with a non-numeric `status` or missing `bodyB64`, which the server-side parser rejects. If either prefix changes, the app silently stops resolving every request (30s timeouts everywhere) and nothing fails at build time. `TODO.md` already contemplates chunking this channel — that change would then have to land in two independent parsers. CLAUDE.md's own structural-twin rule (`src/desktop-server-env.ts` → `apps/desktop/server-env.js`, in this very file) was not applied. **Fix:** compile `src/machine-channel.ts` → `apps/desktop/machine-channel.js` in `scripts/build.ts` with the `AUTO-GENERATED` header, and require it from main.js. If the copies are kept deliberately, record the keep-decision and its reason.
- [ ] **Collapse the third and fourth copies of the base64 Response shim.** *(major, part of the above)* `renderer/machine-relay.js` `respond()` and `terminal.html` `makeResponse()` are the same function and already differ — only the latter has `dataUrl()`.
- [ ] **The relay accepts `hj-machine-request` from any frame, with no `event.origin` or `event.source` check.** *(minor, unverified — but confirmed by inspection during B1 verification)* `renderer/machine-relay.js:18` validates message *shape* only, then forwards to `machineRequest` → shell + filesystem. Today the only sender is `terminal.html` (content tabs are `<webview>` guests and cannot postMessage the embedder), so it is latent — but it is precisely what turns B1 from "third-party code in a preview pane" into "third-party code with a shell", and any future plain `<iframe>` in the renderer (docs pane, preview, OAuth page) inherits shell access by accident rather than by decision. **Fix:** require `event.source` to be a known terminal iframe's `contentWindow` (tabs.js already holds the elements) and reject anything else with a logged 403. Same default-deny discipline as `isRefusedMachineControlPath`. *(Deduped: reported independently by both lenses.)*
- [ ] **The guard test that replaced human enumeration only recognises template-literal fetches.** *(minor, unverified — regex confirmed by inspection)* `src/desktop-machine-calls.test.ts:41` matches `/fetch\(`[^`]*?(\/(?:terminal|files)\/[a-z-]*)/`, requiring a backtick immediately after `fetch(`. `fetch(getServerUrl() + '/files/read')`, `fetch("/terminal/command")`, or `fetch(url)` built a line earlier all pass green and 410 at runtime — the exact silent breakage the test's own comment exists to prevent ("Pick folder…" stopped working last time this was done by hand). The comment's claim "however the base is spelled" is true for one of three spellings. **Fix:** match the path independently of call shape, and make the comment honest about coverage.
- [ ] **Timeout layering is inverted, so a slow command reports a channel timeout instead of the server's real answer.** *(minor, unverified — values confirmed: iframe 35s > main 30s = server 30s)* `executeShellInDir` spawns with `timeout: 30000` (`src/terminal.ts:420`) and then returns what it collected; `machineRequest`'s deadline (`main.js:1322`) is also 30000ms and starts strictly earlier. A ~30s command (`npm ci`, a slow build) shows "Timed out waiting for /terminal/command on the machine channel" and the real truncated output is discarded — the previous plain-`fetch` path had no client deadline and always showed it. **Fix:** each outer deadline strictly longer than the one it wraps (server 30s, main 45s, iframe 50s), so a timeout at a layer always means that layer genuinely lost the answer.
- [ ] **`HALTIJA_MACHINE_CHANNEL=1` is a capability grant that leaks to the whole process subtree.** *(minor, unverified — env inheritance confirmed: `src/terminal.ts:422` and `src/agent-shell.ts:542` both spread `...process.env`)* `buildServerEnv` carefully grants the channel to the public role and `delete`s it for the internal role — then every command the terminal or an agent spawns inherits it. A developer or agent running `bunx haltija --name proj` from the desktop terminal gets a server that starts consuming its own stdin and treats `HJ_MACHINE_REQ` lines there as authenticated machine-control requests, on a process whose stdin may be shared. Silent — one log line in a child's output nobody reads. **Fix:** `const env = { ...process.env }; delete env.HALTIJA_MACHINE_CHANNEL` in both spawn sites. The grant is for one process, not a subtree.

## Completeness gaps and caveats

- **11 of 14 findings are unverified.** Every blocker and both gating majors were adversarially verified; the rest are leads. I independently spot-checked the cheap factual claims of most of them (env inheritance, timeout constants, regex shape, CHANGELOG/npm versions, `UPSTREAM.md` absence, `AGENTIC-IDE.md` lines, relay source) and found each **factually accurate** — but their severity and their proposed fixes have not been adversarially tested.
- **Two dedupes applied.** "Machine-channel implemented twice" and "relay has no origin check" were each reported independently by the correctness and blast-radius lenses; merged, keeping the sharper wording. That two lenses converged on both raises confidence despite neither being formally verified.
- **Lenses not run at this depth:** efficiency, dedicated security, ecosystem, practices, structural audit. Given that a *fast* pass surfaced a supply-chain RCE, **the remediation should be re-reviewed with the security + blast-radius lenses over the remediation diff**, and a full nine-lens pass is due before the next minor regardless.
- **No test-coverage gaps from red tests** — the suite is fully green with nothing skipped. The coverage concern here is the opposite shape: the one guard test standing in for human enumeration (`desktop-machine-calls.test.ts`) is narrower than its comment claims, and `apps/desktop/main.js`'s protocol implementation has no test at all.
- **Not investigated:** whether the shipped v1.12.7/v1.12.8 artifacts warrant an npm deprecate/advisory for B1. That is a judgement call for the maintainer, but it should be made deliberately rather than by default — the vulnerable code is installable right now.
