## Blockers (must fix before tagging)

### B1 — `runFile()` / `suite()` are outside the #42 boundary, so the published library still drives a browser nobody chose
**`src/test.ts:346` (`runFile`), `src/test.ts:415` (`suite`)** — verified in source *and* in the shipped `dist/test.js`.

`refuseMutationOnSharedDefault()` is called at exactly five sites: `click` (276), `type` (281), `press` (286), `navigate` (296), `refresh` (300). `runFile()` and `suite()` call neither it nor `warnIfSharedDefault()` — they `POST` straight to `${this.baseUrl}/test/run` and `/test/suite`. In `dist/test.js` the refusal string is at 654 while the unguarded fetches sit at 773 / 806 / 833, and `package.json` exports `./test` → `dist/test.js`.

The module header (`src/test.ts:18-20`) advertises `await hj.suite('./tests')` as its usage example. A consumer who upgrades to 1.12.9, sets no `HALTIJA_URL`/`HALTIJA_PORT`, and calls it resolves to `http://localhost:8700` with `source: 'default'` and executes every `navigate`/`click`/`type` step in the suite against whatever browser answered — with **no throw and no stderr line at all**, since the suite path never reaches the warn helper either. That is the 2026-09-03 incident this release is written about, on the path it documents first.

The completeness claim compounds it. `CHANGELOG.md:30` heads the section "`haltija/test` no longer mutates a browser nobody chose (#42)" and the body enumerates "`navigate`, `click`, `type`, `press`, `refresh` now throw" — an adopter has positive reason to believe the hazard is closed. This is the same false-completeness shape the release's own B3 was opened about.

**Fix:** call `this.refuseMutationOnSharedDefault('run tests against')` at the top of both `runFile()` and `suite()` (a JSON fixture is mutation by definition — `navigate` is step 1 of every file in `tests/`). Decide `focus`/`blur` (lines 290-291) explicitly rather than by omission. Add a case to `src/test-shared-default.test.ts` covering the runner path (stub `fetch`; no network call) so the guard set cannot silently fall behind the API surface again.

**Re-review scope:** correctness + blast-radius over the remediation diff only. Confirm `tests/haltija.test.ts`'s `explicitlyTargeted` skip still short-circuits before the new throw, and that the new test makes no network call.

*One correction carried from verification, for accuracy:* the in-repo `tests/haltija.test.ts:131` call is **not** currently a live reproduction — that file computes `explicitlyTargeted` and is wrapped in `describe.skipIf`, so our own lane is protected by its own local guard. The library we ship to adopters is not. The hazard, the reachability, and the false claim all stand.

## Majors — decide before publish (fix, or record an explicit keep-decision)

### M1 — `isLocalOrigin` accepts the literal `Origin: null`, so the B3 gate is bypassable; and the "local origin" claim is stronger than the code
**`src/ws-origin.ts:22-34`, `src/server.ts:4270`, `src/ws-origin.test.ts:14-15`** — verified, reproduced end-to-end with real Chromium and a real 1.12.9 server. Two vectors on one gate:

- **Browser vector.** Line 27 returns `true` for the string `'null'`. A page on a hostile origin embeds `<iframe sandbox="allow-scripts" srcdoc="…new WebSocket('ws://localhost:8700/ws/terminal')…">`; the opaque origin serializes to `Origin: null`, passes the gate, and the server immediately volunteers `{type:'identity', shellId, cwd}` (`src/server.ts:4315`) plus the `file-touched` stream of absolute paths. Reproduced: `Origin: https://evil.example` → 403; `Origin: null` from a real sandboxed srcdoc frame → 101 + `STOLEN: {"type":"identity","shellId":"shell-1","cwd":"/Users/tonioloewald"}`. `/ws/agent` is in `MACHINE_SCOPE_SOCKETS` too, and `broadcast()` (`src/server.ts:700`) forwards command responses — `/tree` output, `eval` results — to agent sockets.
- **Non-browser vector.** Absent Origin is also allowed and `Bun.serve` is called with no `hostname` (`src/server.ts:4702`), so it binds `0.0.0.0`. Verified: `curl` and a raw upgrade to `/ws/terminal` from a non-loopback interface address, with no Origin header, both succeed. Exposure here is not new (the whole REST surface is LAN-reachable without `--token`) — the propagating cost is the **claim**: the function name, the 403 body ("machine-scope sockets require a local origin"), and the shipped CHANGELOG line all read as "only this machine".

Read-only disclosure, no execution path — which is what keeps it out of blocker territory. The exemption is also *necessary*: `apps/desktop/main.js:369` uses `loadFile()`, so the legitimate renderer genuinely sends `Origin: null`. Origin alone cannot separate the two.

**Fix:** require positive proof instead of a permissive default — have the desktop main process append the server token (or a per-launch nonce in the `terminal.html` query string) to the `/ws/terminal` URL in `tabs.js` and accept `Origin: null` only on a match; and/or, when Origin is absent, additionally require a loopback peer via `server.requestIP(req)`. If deferred, then **at minimum** stop the code, the test name, the 403 body and the CHANGELOG from asserting a property they do not have: say plainly that `Origin: null` is forgeable by a sandboxed/`srcdoc`/`data:` frame and that this gate raises cost rather than closing the hole. Note the same release amended `src/machine-channel.ts` away from an unqualified claim with the comment "this file is read as ground truth" — the identical discipline applies one file over.

### M2 — 1.12.7 / 1.12.8 are still `latest` on npm, un-deprecated, carrying the vectors this release exists to fix
**(cross-cutting)** — verified live: `dist-tags.latest = 1.12.8`; 1.12.6/1.12.7/1.12.8 all `deprecated: none`; 1.12.9 not yet published.

The published tarballs ship `apps/desktop/terminal.html` with unpinned rolling `cdn.babylonjs.com/babylon.js` (lines 2038-2039) loaded into the frame that holds the `postMessage` relay to `spawn('sh','-c')`, with no iframe `sandbox` (`tabs.js:243`), CSP headers deleted globally (`main.js:667-670`), and a relay that validates message *shape* only (no `isKnownTerminalFrame` sender check — that is new at HEAD). Their `dist/server.js` upgrades `/ws/terminal` with no origin check at all. `npm i haltija` today, or any `^1.12.0` lockfile refresh, installs that.

Two corrections that *broaden* rather than weaken the finding: 1.12.6 has no Babylon vector but *does* serve `/terminal/command` with no `isRefusedMachineControlPath`, i.e. network-reachable shell execution; and the `/ws/terminal` disclosure predates 1.12.7 — it is first fixed at HEAD, not introduced by those releases.

`reviews/1.12.9-tier1-v1.12.6-to-v1.12.8.md:134` records this verbatim as "Not investigated … the vulnerable code is installable right now", and nothing in the diff, `CHANGELOG.md`, or `TODO.md` addresses it. No existing mechanism signals affected users (legacy retirement keys on 1.4.0; skew warning only compares `hj` to its own server).

**Fix:** make it a recorded release step, not a default. After publishing 1.12.9:
`npm deprecate haltija@"1.12.7 - 1.12.8" "Security: unpinned CDN script in a privileged desktop frame and cross-origin /ws/terminal disclosure — upgrade to >=1.12.9"` (additive and reversible), and state in the CHANGELOG's security section which versions are affected. If the maintainer decides against it, **record the keep-decision and its reason** — the review asked for a deliberate judgement and silence is not one.

### M3 — the widened `fetch()` guard test verifies a copy of its own regex, so a regression passes green
**`src/desktop-machine-calls.test.ts:50-52` vs `:71-72` and `:81`** *(unverified — the mechanics are confirmed by reading; no adversarial pass ran)*

The scanner builds `/(?<![.\w])fetch\s*\(/` plus `/['"`]?(\/(?:terminal|files)\/[a-z-]+)/` inline; both meta-tests (`recognises non-template call shapes…`, `does not flag the sanctioned helpers`) re-declare those regexes literally instead of calling the scanner. Narrow the scanner back toward the template-literal-only form that shipped the broken "Pick folder", or drop the `(?<![.\w])` guard so `machineFetch(…)` starts being flagged, and both meta-tests stay green against their private copies. That is exactly the drift-passes-green mode the file's own header describes, reintroduced inside the rule's own tests.

Second gap, same finding: the scan is scoped to `apps/desktop` only, while `src/task-board.ts` — a shipped component — `fetch`es the refused `/terminal/command` at **lines 380, 711, 734, 747, 760** (confirmed by grep). That is the same silent-410 class the guard exists to catch, outside its scope.

**Fix:** extract one exported pure function (e.g. `refusedMachineFetchOnLine(line): string | null`, next to `isRefusedMachineControlPath` in `src/machine-control.ts`); have the directory scan and every sample test call it, including must-NOT-match samples. Decide whether the scan should cover `src/` too.

Sanity-check before acting.
