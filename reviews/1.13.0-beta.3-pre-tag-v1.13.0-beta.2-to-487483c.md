## Blocker

1. **`hj doctor` judges the focused tab, not the tab commands go to, when origins are declared**
   (#821; found independently by correctness and blast-radius).
   - Commands from a project with `.haltija.json` / `HALTIJA_ORIGINS` are pinned to the matching
     tab. Doctor took `tabs.find(w => w.focused)` and sent its paint probe untargeted.
   - False failure, a regression from beta.2: our tab visible, another project's hidden tab holds
     focus. Doctor exits 1 and advises bringing the other project's tab forward. beta.2 exits 0.
     Reproduced against a fake server with both versions.
   - False pass: our tab hidden, theirs focused and visible. `observability.target` names theirs.
   - Six sibling checkouts on this machine declare origins.
   - **Clears when:** an e2e case with `HALTIJA_ORIGINS` set passes in both directions and
     fails with the fix reverted, and the paint probe carries `?window=<target>`.

## Major

- **The launcher never stops its server child, so the suite leaves servers running** (#1080).
  - `https.test.ts` and `both-mode.test.ts` moved to the shipped `bin/tosijs-dev.mjs`, which spawns
    `dist/server.js` and forwards no signal on the `--server` path. `afterAll`'s `kill()` reached
    the launcher only.
  - Observed: 34 servers from this checkout with ppid 1, about 1.1 GB, the oldest from the day
    #1080 landed. They were isolated (temp registry, no install, no retire) but held ports in the
    test range, where a later run could be answered by stale code.
  - The same gap orphans the server for any user whose supervisor SIGTERMs `haltija --server`.
    That part predates the diff.
  - `scripts/assert-no-machine-footprint.sh` checks files, not processes, so no gate saw it.
  - **Clears when:** signalling the launcher stops the server (test fails with the fix reverted),
    and the footprint gate fails on a surviving server process.
- **#1079 has no test, and its new reach is under-explained.**
  - An explicit `--https-port` can now identify the holder over TLS and ask it to stop, which
    ends that server's HTTP listener too. Deliberate, in the CHANGELOG, receipt-logged, gated by
    `HALTIJA_NO_RETIRE`, and narrower than before in every other respect (read, not run).
  - `--help` does not say the flag stops the holder, and the server's own banner suggests the flag
    ("pass --https-port for a stable one").
  - **Clears when:** a two-server test shows an explicit HTTPS port stopping a `both` holder and
    a non-explicit one leaving it alone; `--help` and the banner say what the flag does.

## Docs (naive read)

- Nothing in `TEST-IN-BROWSER.md` said what must be running, how to install, how to target a
  server, or what a failure looks like. `markBrowserTestRan` / `assertBrowserTierRan` were used and
  not explained.
- The first sample used `hj` with no port named. On the shared 8700 `click`/`type`/`press` refuse,
  but `read`, `clickAt` and `dragFrom` go through `eval`, which is exempt, so they act on whatever
  tab is focused there. Pre-existing; filed as virta #3120.
- The engine table called every haltija action "realistic". `press` through a haltija client is one
  `keydown` at `body`. Pre-existing; filed as virta #3121.
- CHANGELOG: "no longer marked experimental" was true of the skill but not of the `/map` API
  description; "`/docs` said…" should be `/llms.txt`; the `observability:` line prints when a tab
  is connected, not on every run, and the frame age needs a 1.12.6+ widget.

## Minor

- `bin/tosijs-dev.mjs` still printed "Reach for --headless when you need Firefox/WebKit coverage"
  in the Playwright-missing error.
- `BrowserBridge.eval` now resolves to `unknown`, so code that calls `.eval()` on a
  `BrowserBridge`-typed value and reads a property stops compiling. Implementers are unaffected
  (checked against `HaltijaTestClient`, `DevChannelClient`, a `Promise<any>` bridge, a real
  Playwright `Page`, and tosijs-editor's bridge). Needs a CHANGELOG line.
- `waitForServer`: its fetch has no abort signal, so a port that accepts and never answers hangs
  past the deadline; a signal-killed child reports "code null"; it accepts a 200 from the port even
  if its own child has exited.
- `hj map`: the read-only note always ends with a "Run them with…" line, even after "It exposes no
  actions".
- Doctor's no-focus fallback takes the first visible tab; the server takes the most recently seen
  active one. Same verdict, possibly a different label. Filed.
- #1079: `requestShutdown` treats a 500 ms abort as "gone", and the bind that follows is
  unguarded. The HTTP path has the same shape. Filed.
